# BASTOOGE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VST3 decoder for the S.T.OOGE mk2g — `bamodulex` plus a fitted bell and phase-matching all-pass on W and a Linkwitz-Riley high-pass on X, Y, Z — with one free control (the dipole cut), a test selector and a bypass.

**Architecture:** The constants are fitted offline in `dream-stone` (Python) and copied, with provenance, into a new Faust library `seam.st.lib` (the specification) and its C++ mirror `plugins/_common/seam_st.h`.
The filters are Simper SVFs, the C++ side of `fi.svf`, so Faust and C++ share one structure and stay stable while the cut moves.
The plugin is a hand-written SingleComponentEffect on the `bamodulex` layout, with a pure DSP engine header tested without the SDK.

**Tech Stack:** Python 3 + numpy + scipy (dream-stone `.venv`, pytest); Faust 2.88; C++17, VST3 SDK + VSTGUI, CMake (Xcode generator), doctest.

**Spec:** `docs/superpowers/specs/2026-11-18-bastooge-plugin-design.md` (seam-ltm). Read it before any task.
