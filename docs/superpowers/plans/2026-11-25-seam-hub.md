# SEAM hub and session sheet — Implementation Plan (plan 1 of 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `calbus` with `libseamhub`, the suite's in-process message hub (members, states, proposals with a per-receiver lifecycle) and its single-writer session sheet, and migrate `multipink`, `ltglide` and `strx` onto it with no change in what the operator sees, except that the sheet now records the session.

**Architecture:** One shared dylib, plain C ABI (`seam_hub_v1_*`), loaded by every member through a header-only `HubClient` (dlopen, null mode on absence or version mismatch), exactly as `calbus` is today.
States reuse the `calbus` per-slot seqlock (wait-free from the audio thread); proposals live in a mutex-guarded bounded store touched only from GUI threads; a background thread inside the dylib is the only writer of the sheet.
The sheet's grammar lives in a pure header so it can be tested without the dylib, and a Python parser in `tools/` reads it back.

**Tech Stack:** C++17, CMake (Xcode generator, multi-config), doctest, VST3 SDK (plugins only), Python 3 (parser).

**Spec:** `docs/superpowers/specs/2026-11-25-seam-hub-design.md` — sections *Design 1* (the hub), *2* (the sheet), *4* (the migration).
The detector (plan 2), the shared decoder engine and BASTONE (plan 3), the fit and the exchange (plan 4) and BASTOOGE's second edition (plan 5) are separate plans; this plan defines the whole catalogue's layouts now so the ABI does not change under them.

## Global Constraints

- No lock, allocation or disk access on the audio thread; `publish_state` is the only hub call allowed there.
- A missing or mismatched dylib never changes a member's sound: the client enters null mode and every call is a no-op.
- Every handle member is initialised to `SEAM_HUB_NO_HANDLE` (−1), never to `0`.
- Every ABI struct has its `sizeof` pinned by `static_assert` in `seam_hub.h`; a layout change bumps `SEAM_HUB_VERSION`.
- Applying or ignoring a proposal requires `byOperator = 1` in this version: no member acts on what it hears by itself.
- The sheet is append-only, one event per line, written only by the hub's writer thread, always written whether or not a detector is loaded.
- Comments and docs follow the suite's voice: explain *why*, cite files and lines, sentence per line in Markdown.
- Build: `cmake -B build-test -DSEAM_BUILD_TESTS=ON -DSEAM_BUILD_PLUGINS=OFF` for tests; tests run with `ctest --test-dir build-test -C Debug -R <name>`.
- No plugin outside `multipink`, `ltglide`, `strx` is touched (no speculative peer awareness, `CLAUDE.md`).

## Review Focus

1. **Two hub versions in one host** (an old bundle and a new one loaded together): the older client must see a version mismatch and run in null mode, never read a foreign layout — test in Task 6.
2. **The host quits while the writer is flushing**: unregistering the last member must flush every queued line and join the thread without hanging — test in Task 5.
3. **The sheet folder is on an unmounted volume** (`/Volumes/Aleph`): no call blocks, lines are held up to the bound, the status says so, and they are written when the folder returns — test in Task 5.
4. **More than 32 members**: the 33rd registration returns `SEAM_HUB_NO_HANDLE`, the plugin still makes sound, the sheet records nothing for it — test in Task 2.
5. **A host running plugins in separate processes** (Reaper's "run as separate process"): each process has its own hub, so two sheets are written in the same folder; their names must not collide — the file name carries the process id, test in Task 5.

typedef enum { kSeamHubNone = 0, kSeamHubArrived = 1, kSeamHubShown = 2,
               kSeamHubApplied = 3, kSeamHubIgnored = 4 } SeamHubLifecycle;

typedef struct { uint32_t test, bypass, stoneOfModel, _pad;   /* test 0..4 Normal,W,X,Y,Z */
                 double cutHz;

    uint32_t kind, stoneId, active, _pad;

    union { struct { int32_t slotStart, slotCount; } pink;
            struct { uint64_t passCounter; int64_t passStartSample;

                     uint32_t sweepMode, diracMode; } glide;

typedef struct { double hz, compDb, levelDb, settled; } SeamHubBand;
typedef struct { int32_t bandCount, hasDecoder; double integrationSec, sourceLevelDb;

typedef struct { uint32_t type, _pad; double hz, q, gainDb; } SeamHubSection;
typedef enum { kSeamHubBlockCommon = 1, kSeamHubBlockDifference = 2 } SeamHubBlock;
typedef struct { uint32_t block, count; double residualRmsDb, residualMaxDb, offsetDb;
                 double fitLoHz, fitHiHz, roomLimitHz; uint64_t fromIds[4];

typedef struct SeamHubProposal {
    uint64_t id;                       /* assigned by post(); 0 before */
    uint32_t type, stoneId;
    uint32_t authorMember, authorInstance;   /* assigned by post() */
    int64_t  postedUnixMs;                    /* assigned by post() */

} SeamHubProposal;

typedef struct { uint32_t member, instance, says, hears;   /* member = registry index */
                 char name[SEAM_HUB_NAME_LEN];
                 uint32_t hasState, _pad; SeamHubState state; } SeamHubMember;

typedef struct { char path[512]; uint32_t writing, pendingLines; uint64_t droppedLines; } SeamHubSheetStatus;

typedef struct SeamHub SeamHub;

uint32_t seam_hub_v1_version(void);
SeamHub* seam_hub_v1_get(void);
int32_t  seam_hub_v1_register(SeamHub*, const char* name, uint32_t says, uint32_t hears);  /* mutex */
void     seam_hub_v1_unregister(SeamHub*, int32_t handle);                                 /* mutex */
void     seam_hub_v1_publish_state(SeamHub*, int32_t handle, const SeamHubState*);        /* RT-safe */
int32_t  seam_hub_v1_members(SeamHub*, SeamHubMember* out, int32_t max);                  /* GUI */
uint64_t seam_hub_v1_post(SeamHub*, int32_t handle, SeamHubProposal* inout);              /* GUI; 0 = refused */
int32_t  seam_hub_v1_proposals(SeamHub*, uint64_t afterId, SeamHubProposal* out, int32_t max); /* GUI */
int32_t  seam_hub_v1_lifecycle(SeamHub*, int32_t receiver, uint64_t id);                  /* GUI; SeamHubLifecycle */

**Interfaces:**
- Consumes: Task 2 (members, their `hears` masks, their state's `stoneId`).
- Produces: `post`, `proposals`, `lifecycle`, `transition`, with these rules:
  - `post` refuses (returns 0) when the handle is invalid or the type is not in the author's `says`; it assigns `id` (monotone from 1, never reused), `authorMember`, `authorInstance`, `postedUnixMs`; stores a copy; evicts the oldest past `SEAM_HUB_STORE`.

  - Every successful `post` and `transition` enqueues a sheet line on Task 2's queue; tests read them through `seam_hub_test_recent_lines`.

The grammar, fixed here so the parser and the formatter agree:

```
# SEAM hub sheet
# started: 2026-11-25 14:30:02   pid: 4711   hub: 1
14:32:07.412  strx#1        says      band-table #12  stone 1  decoder W cut 160  31 bands  646.6 s
  | band  hz        comp_db  level_db  settled
  | 20    19.95     +3.0     -41.2     1.00
14:33:40.020  bastone#1     shows     band-table #12
14:33:52.881  operator      applies   band-table #12  on bastone#1
14:33:52.903  bastone#1     says      sections #13  common  6  rms 0.8  max 1.9  offset -3.2
  | peak        111.4  2.00  -6.0
14:40:00.000  multipink#1   state     pink  stone 1  slots 0-3  -23.0 dB  active
14:41:00.000  hub           sheet     folder unreachable, 120 lines held
```

Event line: local time `HH:MM:SS.mmm`, two spaces, `who` left-aligned in 12, two spaces, verb left-aligned in 8, two spaces, object (free text, no newline).
Continuation line: exactly `  | ` then the row.
Verbs: `arrives`, `leaves`, `state`, `says`, `shows`, `applies`, `ignores`, `sheet`.
`arrives` objects list the masks by type name (`says pink  hears -`).

### Task 5: The writer, the folder, the session

**Files:**
- Modify: `plugins/_common/hub/seam_hub.cpp`
- Test: `tests/seam_hub_writer_test.cpp`; a ctest `hub_sheet_roundtrip`

**Interfaces:**
- Consumes: Task 3's line queue, Task 4's formatter.
- Produces: `sheet_status`, `sheet_set_folder`, `sheet_new`, and the behaviour:
  - The writer thread starts at the first `register` and is stopped and joined at the last `unregister`, after a final flush; the join happens outside the registration mutex.
  - It wakes every 250 ms: snapshots the states, enqueues a `state` line for each member whose state differs from the last written one, then appends the queued lines and `fflush`es.
  - Folder: `SEAM_HUB_CONF` (env, for tests) or `~/Library/Application Support/SEAM/hub.conf`, line `sheet-folder=<path>`; default `~/Documents/SEAM/sheets`, created if missing.
    `sheet_set_folder` writes the conf and takes effect on the next sheet.
  - File name `YYYY-MM-DD-HHMMSS-<pid>-seam-sheet.txt`, from the session start.
  - If the folder cannot be opened, lines are held up to 10 000; beyond, the oldest are dropped and counted; `writing = 0`; one `hub  sheet  folder unreachable, N lines held` line is written when it comes back, before the held lines.
  - `sheet_new` closes the current file and opens a new one at once (new start time in the name).
